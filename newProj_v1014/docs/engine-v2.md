# 渲染引擎 v2（2026-10-16）

这一轮把"能画出镜头"升级成"有一套引擎"。目标不是加框架，而是补上此前明显缺失的四层：**调色后期、运动原语、动态字体、聊天界面组件**，并让音频数据真正驱动画面。

原来的 `src/p0.js` / `src/p1.js` 仍然保留，它们现在只负责"这一镜画什么"；以往混在里面的通用绘制逻辑抽到 `src/engine/`。

## 分层

| 文件 | 职责 |
| --- | --- |
| [`src/engine/motion.js`](../src/engine/motion.js) | 运动原语：缓动、过冲、脉冲、弹簧、拖影、抖动、确定性随机、选项插值 |
| [`src/engine/features.js`](../src/engine/features.js) | 歌曲时间特征采样器：分频包络、节拍网格、起音查询 |
| [`src/engine/type.js`](../src/engine/type.js) | 动态字体：适配、折行、逐字弹出、打字机、乱码解码、横向擦除、引线 |
| [`src/engine/grade.js`](../src/engine/grade.js) | 后期调色：选择性辉光、色差、闪光、扫描线、暗角、逐帧颗粒、淡入淡出 |
| [`src/engine/chat.js`](../src/engine/chat.js) | DeepSeek Harness 风格聊天组件：窗口、消息行、流式文本、思考行、工具卡、输入区、状态点、胶囊、上下文环 |
| [`src/engine/stage.js`](../src/engine/stage.js) | 舞台：持有离屏内容层，负责相机合成与后期，是"歌曲时间 → 成帧"的唯一入口 |

## 每帧的顺序

```
stage.begin()          清空内容层，返回给它画画的 ctx
  …镜头把平面内容画进去…
stage.present(target,t) 相机合成 → 色差 → 辉光 → 闪光 → 扫描线 → 暗角 → 颗粒 → 淡出
```

镜头只画平面内容，**不允许自己碰相机和调色**。这样同一个时间点的画面对任何跳转都一致。

## 音频接入

`tools/build-audio-features.py` 从本机 WAV 生成 `data/audio-features-v1.json`（不入 Git）：

- 100 Hz 的 `rms / low / mid / high` 四条序列，base64 打包的 uint8
- 节拍网格：**129.9954 BPM，相位 0.31 秒**（与 `docs/storyboard-v1.md` 记录的 130.00 / 0.328 一致，差 18ms，小于分析窗口）
- 1613 个起音，各带强度

采样器的 `envAt()` 用**无状态峰值保持**（最近窗口内的 `value·exp(-release·age)` 取最大），而不是逐帧累积。这是为了守住确定性：暂停、拖动进度条、逐帧导出必须得到同一帧。

目前音频驱动的是**调色层**（全部镜头同时受益）：

```js
glow   = base * (0.80 + 0.42 * lowEnv) + 0.12 * beatPulse * onsetStrength
zoom   = 1 + 0.007 * lowEnv + 0.002 * barPulse
```

实测 240 个采样点的辉光在 0.343–0.564 之间连续变化（208 个不同取值），画面会跟着低频呼吸、跟着鼓点轻微上浮。以前这套数据算出来了但渲染器一个都没用。

## 运动密度：这一轮最重要的一件事

引擎做完之后，我做了 `tools/measure-motion.py` 和 `tools/measure-shot-motion.mjs`，把"效果不好"变成数字：逐帧算相邻帧的平均灰度差，低于阈值算"静止帧"。

第一次实测（59.223–95.465 秒，2177 帧）：

| | 平均帧间差 | 静止帧占比 | 最长静止 |
| --- | --- | --- | --- |
| 只有旧画法 | 0.585 | **80.0%** | 1.32 s |
| 加了引擎和调色 | 0.621 | 78.7% | 1.32 s |

也就是说：**引擎搭好了，但镜头本身没在动**。S16/S20/S21/S22/S27 这些镜头九成以上的帧几乎完全不变——这正是"像幻灯片"的原因。

于是加了 [`src/engine/ambient.js`](../src/engine/ambient.js)：一层盖在所有镜头之上的深海环境运动——漂移光柱、每拍扫过全画面的焦散光带、按拍扩散的声呐环、以及上浮的悬浮颗粒。

**关键教训**：第一版做的是细颗粒和微弱光带，测出来只把平均差从 0.585 提到 0.621，等于没用。**小面积、低对比的细节在观感上根本不构成运动。** 真正有效的是**大面积同时变化**——所以第二版改成宽光柱 + 每拍横扫的光带，静止帧立刻从 80% 降到 32%。

| | 平均帧间差 | 静止帧占比 | 最长静止 |
| --- | --- | --- | --- |
| 强化后的环境层 | 1.301 | **35.9%** | 0.30 s |

声呐环的圆心跟着每个镜头自己的构图焦点走（见 `main.js` 的 `AMBIENT_FOCUS`），不是死板地画在画面正中。

## 转场

[`src/engine/transitions.js`](../src/engine/transitions.js) 提供 9 种可用转场：`cut / fade / flashcut / scan / circle / push / slices / glitch / dissolve`。舞台现在持有 A、B 两层：当前镜头画进 A，转场期间搭档镜头画进 B，合成后再调色。

转场表按**进入镜**命名，只给少数边界配了成形转场，其余保持硬切——这是借用参考片的判断（进出版画用硬切；画面里有脸时只用切或淡入淡出），不是它的代码。

一个必须踩过才知道的坑：**字幕不能跟着转场一起被切开**。dissolve 会把大字标题切成碎块，看起来像文字坏了。所以字幕改成"镜头只规划、舞台在合成之后、调色之前绘制"（`drawCaption` + `stage.present` 的 overlay 回调）。这样字幕永远完整，但仍然会吃到颗粒和暗角。

顺带一个规则：转场期间**搭档层不画字幕**，否则两句话会叠在同一个位置。

## 模型内部的可复用语言

五十六镜里大约二十镜是"模型内部"，所以这部分做成共享词汇而不是逐镜手画：[`src/engine/model.js`](../src/engine/model.js)

- `nodeGrid` — 漂移的点阵（周期性取模，换行无缝），节点逐个脉动，给整幅画面连续运动
- `signalPath` — 一条路径上同时跑多个数据包（各自相位不同），所以链路永远不是静止的单次扫过
- `dataColumns` — 滚动的终端字符列，提供 TUI 质感
- `waveform` — 取音频某条序列的一段窗口画成条状波形，让画面**看得出在跟音乐**
- `node` / `beatRings` — 发光节点与每拍扩散的环

[`src/engine/audio.js`](../src/engine/audio.js) 把特征表做成只读单例，镜头可以直接 `sampleAt(t)`。表加载完就不再变，所以"帧只依赖 t"这条性质没有被破坏；表缺失时返回中性值，画面退化但不会崩。

S16（连接回路）和 S19（留存记忆）已按这套重做。S16 从"两条细弧加一个点"变成"一张会脉动的网格里、两条链路各跑三个数据包、端点按拍扩散"。

## 逐镜相机

静止的版画镜头靠**相机**而不是靠叠加层来获得生命：`main.js` 的 `SHOT_CAMERA` 给每镜一个缓慢推近或拉远（约 1.00→1.05）与构图焦点。这比再加一层贴图更符合"角色出现越近，画面越简洁"的规则。

注意：缓慢推镜在帧间差指标上几乎量不出来（每帧位移不到 0.1 像素），但对观感是有效的——**指标只是下限，不是目标**。

## 角色表演

版画特写不能靠叠加层解决——一张完全静止的 PNG，无论背景光怎么动，看起来还是静帧。所以加了 [`src/engine/portrait.js`](../src/engine/portrait.js)：缓慢的呼吸、起伏与横摆，加上按拍脉冲的轮廓光。

幅度刻意很小：4.5 秒周期上 5px 的起伏，摊到每帧只有约 0.1 像素。**这种量级在帧间差指标上永远看不出来**——它的目的就是观感，而不是数字。所以指标只是下限；这一层的价值要靠眼睛验收。

顺带修掉一个真 bug：`portrait(ctx, catPose(81.351))` 把姿态**永久冻结在 81.351 秒**，整个 S22 镜头里角色一动不动。改成 `catPose(t)` 后 S22 的静止帧从 40.9% 掉到 26.1%。

## 分段登记表

加到第三段时，`main.js` 里已经堆了七张按镜头索引的表（环境预设、焦点、相机、转场、分段渲染、区间、镜头表），每加一段都要改七处。所以抽出了 [`src/segments.js`](../src/segments.js)：**加一段只需要写一个模块 + 在登记表里加一条**。`main.js`、`measure-shot-motion.mjs` 都从登记表读，离线工具不再硬编码分段 id。

## 第三段：S07–S14（29.709–59.223 秒）

关系开始有形状：输入点铺成场、圆作为附件发出去、圆边拉成正弦波、角色被推上台、控制面板改变采样方式、可视区收窄成带、记忆回卷越过零点、两条声道终于对齐。

实测静止帧 30.3%（S12 最好 12.7%，S10 最差 35.7%）。

这一轮从胶片和边界抽查里挖出三个真 bug：

1. **`route()` 传三个控制点时静默产生 NaN**。三次贝塞尔求值函数收到 `undefined` 后整条路径变成 NaN，一路炸到 `createRadialGradient` 才报错。已改成支持 3/4 个控制点，其他数量直接抛错——不再有静默失败。
2. **`align:"start"` 的转场方向是反的**。转场库按「from=旧镜、to=新镜」合成，但起点在切点上的转场被求值时，当前镜**已经是新镜**了。淡入淡出对称所以一直没暴露；scan/circle/push 这类会先擦到旧镜再瞬间跳回新镜。已在 `main.js` 里按 `align` 交换 A/B 两层。
3. **S14→S15 的硬切落在一张近黑帧上**。S15 的窗口原本从全透明开始涨，切过去先是空的。现在窗口提前 0.55 秒开始抬起，并把这条边界改成 `flashcut`——闪光盖住切换，落地时窗口已经成形。

## 第四段：S28–S35（95.465–131.224 秒）

失联段。通道被交给另一端、智能体开始漂移、远端不再回应、角色只剩一张没发出去的伸手图、本端清掉未确认缓存、重连请求被窗口边界拦下。

故事板对这一段的要求是**空靠留白和消息间距**，不是靠音乐变轻，也不是删掉智能体自己的身份。所以这几镜刻意比前三段稀疏：更少的运动元素、更长的停留、环境层压得更低。实测静止帧 38.3%——**比其他段高是故意的**，用来和后面的高潮形成对比。

这一段是分段登记表的第一次实战：新增 p4 只改了 `segments.js` 一条、`main.js` 三行、导出预设一条。

顺带又被自己上一轮加的守卫抓到一次：`route()` 收到 8 个控制点直接抛错（我把它当折线用了）。于是补了 `polyline(points, closed)`——重采样成和 `route()` 相同的 161 点形式，所以 `trace`/`along`/`signalPath` 都能直接用。后面的十二次重连轨道和闭环镜头都要用它。

## 第五段：S36–S43（131.224–162.805 秒）

故障段。被拒绝的路径进入内部路由图，**故障红第一次出现——只标在越界端口上**，三条失败队列由外向内挤压，本端排队自动重连，十二次呼叫沿声呐环推进，六次探针落到同一个空端点，最后路径在她眼前留下一道竖直水光。

故事板对这一段的三条硬约束都落实了：红只标越界端口与局部故障边（**从不整屏铺红**）；十二次呼叫是**一个推进的环**而不是十二个新构图；六次探针是镜内事件而不是六张全屏卡片。

`s36` 的越界端口、`s39` 的十二格环、`s41` 中心圆孔里透出的眼图、`s43` 的水光都是这一段的主要动作。

新增颜色：`C.danger = #e75d69` / `C.dangerDim`。

实测静止帧 36.9%（S41 最好 26.7%，S38 最差 44.2%）。

`route()` 的控制点守卫**第三次**抓到我：s36 的绕行折线给了 5 个点。这个守卫是上一轮加的，连续两轮各抓到一次真实误用——如果当时只是静默产生 NaN，报错会出现在很远的地方。

## 闪帧检查

`tools/check-flash.py`：整帧亮度逐帧求差，统计超过阈值的跳变、最差一秒内的闪帧数（判据 ≤3/秒）、以及最大单帧跳变，并给出跳变最大的三处时间点。

这个工具第一次跑出来的是**错的**：当时用「字节数能被 width×h 整除」来推断帧高，结果选中了 67 而不是 90（`138690` 的一个非常规约数），于是 1541 帧被算成 2070 帧、时长 34.5 秒。**报告数字全错但格式完全正常**——这类错误最危险。改成从 ffprobe 读源尺寸、显式指定缩放输出后，帧数与时长才对上。

## 确定性契约

- 所有随机来自 `hash01` / `mulberry32`，**源码里不出现 `Math.random`**。
- 无跨帧状态：任何函数只依赖 `t`。
- 已实测：先取帧、跳到 95.4/12.0/150.0 秒、再回到 68.3 秒，**调色参数与画布 PNG 逐字节一致**。
- `tools/export-p0.mjs --mode stills` 会自动做反向跳转复验和字幕审计。

## 调色参数怎么调

`grade.js` 的默认值，或 URL 覆盖（`?g_glow=0.2&g_grain=0`）。辉光不是"越亮越好"：本项目素材本身是高对比平涂版画，辉光过强会把它糊成霓虹灯。现在的做法是**先压暗再狠压对比**（`glowBrightness 0.72`、`glowContrast 3.0`），让中调的青色只沾一点，接近白色的皮肤和纸面才真正发光。
