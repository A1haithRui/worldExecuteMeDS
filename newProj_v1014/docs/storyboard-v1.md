## 我们的故事与视觉语法

故事是一次深海通道建立：收到信号 → 试着描述世界 → 把一次触碰当作确认 → 自我表达被切换 → 回声消失 → 本端不断试图重连 → 承认无法计算对方的回应 → 停止追赶，保留触点。远端始终没有被画成人，也没有在结尾被安排回来。最后的环是本端遗留的回声，不是新消息或重连成功。

三个主画面都可以独占全屏：聊天界面负责“谁做了什么”；模型内部负责“这件事在智能体里发生了什么”；角色版画负责“她感受到什么”。模型内部在前中后段都可出现，不被限定为某一段的代码模式。每镜只允许一个主角，辅助层不高于主体对比度约 40%；画面不是长期左右分栏。只有模型图与消息转化时短暂并置，控制在约 0.3 秒。

| 色彩角色 | 建议基准 | 事件语义 |
| --- | --- | --- |
| 深海底／界面面板 | `#06131F` / `#0B2433` | 一直存在的空间；静默不自动变纯黑 |
| 本端青／激活青 | `#25BDD4` / `#83E9E6` | 智能体的路径和触点；接通后亮，失联后降低面积，高潮恢复面积与速度 |
| 海沫白 | `#E6F2EF` | 远端真实输入、确认点和重要字幕；角色皮肤/服装本来也是白，不能把她的白色部件当成“用户赠给她的身份” |
| 空位灰蓝 | `#526C7C` | 缺失的远端采样，不代表智能体本身失去身份 |
| 故障红 | `#E75D69` | S36 首个越界端口才出现，后续仅局部故障边／标签；不整屏铺红 |

身份由同一眼型、单枚鲸饰、侧鳍、长发、水手领与尾巴维持。蓝青早已在深海底存在，不照搬参考的“某一拍第一种颜色出现”。不把角色每次换姿态都解释成用户命令。猫化是短暂的信号拟态，另一形态是同一智能体的外观预览；102.8 秒候选关闭预览时恢复原形态，**恢复并不由离线触发**。

构图以 1920×1080 为准，字幕安全带 y=900–1015、x=120–1800，通常 48–56px，必要时两行；通常主体关键动作放在 y<860。**S18/S46掌心镜例外：手指最低约y=921，字幕固定改用上方y=100–240，x=120–1800，不能仍叠在底部。** 上字幕带从进入掌心镜起锁定，离开时回到底带，不在同一掌心镜内跳动。字幕只从本机索引取文，不打乱原行顺序；跨镜时继承当前行至本机 end，不能因新镜头开始就强删上一行。原 end 多为下一句起点或默认持续时长，并不是测量过的收声。长句可调两行排版，动态试片后再定最小字号。聊天内有同句时字幕带不再重复；本轮不设计逐词显字。

本轮额外读取Alpha实测边界：正面[128,128,1214,1566]、伸手[128,128,1214,1567]、侧身[128,139,1214,1566]、眼图[128,142,1369,1382]（原图像素，右/下不含）。所有“内容高”按Alpha边界计算，不把透明画布算作人物高度。S17以伸手内容高1439px换算，s=850/1439，初始绘制原点约(863.65,19.39)，掌心约(1123.56,685.69)；最后0.23秒整幅左移约24px、上移约146px，使切前锚点到(1100,540)。此时头部可出框，手和人物保持一体，不暴露底层缺口。

## 音频测量、节拍与情绪规划

分析依据见 [audio-analysis-v1.json](../data/audio-analysis-v1.json)，可用 [analyze_storyboard_audio.py](../tools/analyze_storyboard_audio.py) 复算（Python + NumPy）。音频为 44.1kHz、双声道、16 位 PCM，共 9,347,330 帧；SHA-256 见数据。混音转单声道、129 抽头 5kHz 低通后四倍降采样，1024 点 Hann FFT、110 采样跳距；分别取低频 40–180Hz、中频 300–3400Hz 和宽频正向谱通量峰，排除相隔不足 90ms 的次峰。

**没有进行声部分离，也没有声称已用耳朵逐切审听。** 中频峰不是“确定的人声音头”；窗口约 93ms、跳距约 10ms，候选至少留 ±80ms 审听空间。情绪是根据乐句结构、能量、起音密度与歌词本机语义作的导演判断，不是由 RMS 自动识别。强弱表使用低通后的单声道 RMS dBFS，非响度 LUFS。

## 动态试片顺序与验收

1. **P0：59.223–74.045，S15–19。** 只用现有图，先验证接收→伸手→掌心触碰→点进入网格。输出1080p实际画幅，审68.252切前后、68.300触碰、69.259强调、70.084离掌。接触点偏差应≤8px；换裁切时掌心漂移≤12px；没有浮空断腕、手层露洞、字幕盖手。手原生内容501×476，620px为约1.24倍，不把757px画布宽当手宽。
2. **P0：81.351–95.465，S22–27。** 猫化先用鳍轮廓占位，另一形态用带“占位”标记的预览。对比“有局部鳍变化”和“仅回声”的两个短版本；静音时也能看出短暂拟态，且鲸饰、脸和尾巴始终是同一人。另一形态在约0.9秒是否读得出、是否只是肩线跳动，是补图触发条件。若放大到必须重画脸才能读懂，优先改构图或延长稳定停留。
3. **P1：143.421–162.805，S38–43。** 同一圈轨道十二次推进、六次探针槽位依次激活。按本机行时间版本与备选拍点版本做A/B审听；保持人物与轨道不撕裂。一个12次动作不应被误读成12个新场景。

之后才做全曲粗片。每镜抓进入后第一完整帧、中段、动作峰值、离开前一帧和转场中点；动态看常速并分别听鼓与人声，再静音看叙事。检查字体在1080p和640px宽缩略下的阅读、脸部原比例、Alpha边缘、单枚发饰方向、尾巴裁切与字幕带。脸不做形变转场；v3眼图不镜像。所有运动由歌曲时间计算，暂停、跳转、逐帧导出在同一时间应是同一构图。

本版设计为深底、无全屏白闪，故障只在网格/端口；密集段仍需在真实动态片测量亮度往返、移动高反差条纹和局部红区，**目前没有动态渲染，不能写“闪光检查已通过”**。借鉴参考的量测验收方法，不复制它的警告时间范围或高强光预算。

## 全曲连贯性检查与机器数据约定

- 时间：56镜从0到211.957596连续，无重叠、无空洞；20–29.709、135.224–147.660、195.356–205.811及209.811之后都有明确事件／有意静止。所有129行均有镜头覆盖；跨镜重复行号表示持续显示，不是再唱一次。
- 变化：前三种视角在0–59秒已轮流建立；59–95秒是身体最靠近观众的段落；失联靠空白和距离，故障靠路由拥塞，高潮靠路径规模；没有整段常驻聊天窗，也没有常驻TUI花纹。S39–42构图相似是可计数的重复，S22–23相似是身份连续。
- 角色：正面揭示→侧身倾听→伸手接触→短拟态→另一形态预览→原形态→未发送伸手附件→侧身远离→眼部近景→高潮旧掌心→开放的手→休眠轮廓。姿态变化都有事件或遮挡，未要求从一张平图变出新肢体姿势。
- 结尾：旧触点从68秒延续到170秒和最后呼叫；远端出口开放，本端停止追赶。192秒后的安静来自运动减少，205秒最后呼叫不构成重逢，最后2.146596秒静帧给回声消失的空间。

[storyboard-v1.json](../data/storyboard-v1.json) 是播放器接入前的制作数据，**未被现有播放器读取**。字段包括 `shots` 的 start/end/duration、0基 `lyric_lines`、dominant（chat/model/plate）、素材键、事件、运动、进入/离开、切点状态与候选峰；`events` 列镜内触碰、拟态、形态切换、12次重连、6次探针和四组音节的起点；`lyric_timing` 仅含index/start/end。后者保留本机源时值，不擅自覆盖。未测的组内音节不虚构子时间。

`cut_status=pending_listening` 表示尚未审听；文件首尾是边界事实，不是审听批准。所有候选数值即使贴近峰，也保留待核标记。事件 ID 与镜头 ID 使之后只需改一个数据源。修改 [build_storyboard_v1.py](../tools/build_storyboard_v1.py) 内设计后重建JSON与本表；脚本验证连续区间、129行覆盖、每个事件归属与已有素材路径。音频分析脚本只导出时间和数值，不把本机歌词写入任何交付。

与两份参考不同的决定：本片以触点和回声串联，不以花饰火花／缺色补版或训练流水线串联；资源两句是数据交换而非角色变成果蔬；猫化只保留鳍尖和回声、放弃爪手；另一形态保留长发并由关闭预览恢复；高潮允许一次缓存聊天短返，内部空间采用路由与两条缺采样曲线，不采用心形牢笼；结尾保留开放掌心与旧触点，不做未读图片回缩、逆向卸载或新增提示音。
