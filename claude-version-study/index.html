这个分镜表是怎么组织的

  • 一镜一句话。每镜的「对话裡的時刻」栏只用一句英文说清"这是这场对话的哪个时刻"，例如 boot-power 是"电到了客户端：一根头发丝般的线张开成窗口，保护层被打开"。这是审片时唯一的叙事依据。
  • 三种画面分工。介面＝用户看到的对话；版画＝AI 心里的意思与感受；程式码只出现在 EXECUTION 段。每镜只属于一种，不混用。
  • 颜色即状态。off 灰阶 / on 橙 / warm 更暖 / error 红 / ash / dead 熄灭。状态变化只在事件发生时改变，不靠渐变过渡。
  • 剪辑点全部落在节拍网格上。表格给出「小节:拍」，130 BPM、第 0 拍 0.344s；自检会报出任何偏离半拍的剪辑点，当前为 0。
  • 转场由代码推导。每个切点写明进入／离开转场（名称、几拍、是否 flash），转场表按"进入镜"命名，其余保持硬切。版画之间用硬切，有脸的镜头只用切或淡入淡出。
  • 四项自检。歌词覆盖率、剪辑点对拍、每镜是否写明叙事时刻、是否还有后备镜头——全部由 node tools/storyboard.mjs 从代码重新生成并检查，分镜表无法与程序脱节。
  • 时长与节奏。87 镜、平均 2.49 秒；副歌与数数段最短（1.8s / 0.53s），开头与结尾最长（3.8–3.9s）。密与疏是有意的对比。
