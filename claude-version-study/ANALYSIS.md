# 参考片分镜解剖：它到底怎么排的，我们能拿什么

对象：隔壁 `world-execute-me-lyric-mv`（Claude 歌词 MV 第四版），commit `2073b0c`。
方法不是读它的文章，而是**把它的镜头清单导出来逐镜核对**（`tools/extract-shots.mjs`），再用它自己渲染的全片切出 87 个剪辑。所有数字都来自它的代码，不是转述。

可交互版本：`index.html`（双击打开）。原始清单：`data/shots.json`。

## 2. 一镜一句话（最重要的那条）

每个镜头在代码里必须写一个 `moment`：**一句英文，说清"这是这场对话里的哪个时刻"**。分镜表的这一栏就是审片时唯一的叙事依据——不点开画面也能判断这镜在讲什么。举例：

- `boot-power`：电到了客户端：一根头发丝般的线张开成窗口，保护层被打开。
- `c1-happy`：她把自己长什么样发成一张图片，每一下鼓点印一色；用户的指针停在她张开的手里，留下一个心。
- `c1-trap`：用户说她不是真的。她的回答是把两个人一起数进同一个窗口。

同一镜还有 `layout`（构图）与 `state`（颜色状态）。**一镜只属于三种画面之一**：介面（用户看到的对话）／版画（AI 心里的意思与感受）／程式码（只在 EXECUTION 段）。三种不混用。

## 3. 剪辑点全部锁在节拍网上

130 BPM、第 0 拍在 0.344 s、一拍 0.4615 s。分镜表给出每个切点的「小节:拍」，并且有一项自动检查：**任何偏离半拍网格超过 2 ms 的剪辑点都会被告警**。当前结果：**0 例外**（87 个切点全部落在拍/半拍/小节线上，只有歌曲开始前那 5 秒不算，因为那时还没有拍）。

顺带说明：我们的音频分析早就算出同一套网格（129.9954 BPM、相位 0.31 s，与它的 0.344 差 18 ms，小于分析窗口）。**差别不在数据，而在我们从来没拿它检查过剪辑点。**

## 4. 转场由代码推导，而且用得极省

每个切点写明进入／离开转场：名称、几拍、是否 `flash`。转场表**按"进入镜"命名**，没配成形转场的边界保持硬切。规则是：版画之间用硬切；**画面里有脸时只用切或淡入淡出**。`flash` 是显式参数（例如 `cut, flash 0.9`），不是附带效果。

它实现了 **15 种**转场（`cut / fade / glitch / scan / circle / diag / grid / zoom / shatter / dissolve / winclose / winpop / push / slices / flashcut`，GLSL 混色），但实际用出去的极少：

| 进入转场 | 参考片用了多少次（共 87 镜） |
| --- | --- |
| hard cut | **74** |
| push | 3 |
| zoom | 3 |
| scan | 3 |
| glitch | 2 |
| fade | 1 |
| slices | 1 |
| 合计非硬切 | **13（15%）**，其中 8 个带 flash |

**这是我们和它差距最大的一项。** 我们的片子有 55 个内部边界，却显式配了 **40 条成形转场（73%）**，其中 13 条是 `dissolve`、9 条带 `flash`。它每 6.7 个边界才用一次成形转场，我们每 1.4 个就用一次——再加上每镜都在跑的环境层运动，观众几乎没有"干脆地切一下"的时刻。**这大概是"感觉做得有点杂"最主要的来源。**

## 5. 四项自检（这才是它最值得抄的部分）

`node tools/storyboard.mjs` 从代码**重新生成**分镜表，并同时断言四件事。当前全部通过：

| 检查 | 结果 |
| --- | --- |
| 歌词覆盖 | 全部 129 行都有对应镜头 |
| 剪辑点对拍 | 所有剪辑点落在拍/半拍/小节线上 |
| 对话时刻 | 每个镜头都写明了 `moment` |
| 后备镜头 | 无（任何 `todo-` 前缀的镜头都会被报出来） |

**分镜表无法与程序脱节**，因为表是生成的；**未完成的地方无法藏起来**，因为 `todo-` 会被点名。对比我们：分镜是设计稿、镜头是手写代码，两边靠人自觉对齐。

## 6. 我们能直接拿走的五件事（按性价比排序）

1. **给每一镜补一句中文 `moment`**，并让审片台显示它。我们已有 `picture_event`，但播放器和审片台都不读；补上以后审片不用再猜这镜在讲什么。
2. **把"剪辑点对拍"加进我们的工具链**。网格数据我们已经有了（129.9954 BPM / 相位 0.31 s），只需列出偏离 >2 ms 的边界。这是零成本的客观检查，能立刻告诉我们哪些切点"听着别扭"其实是没落在拍上。
3. **把后备镜头变成一等公民**。我们现在有两处占位藏得很深：猫化的 0.28 秒轮廓、另一形态画面上那行 `Outline only`。参考片用前缀 + 自检把它们钉在明面上。我们至少要有一条命令能列出所有未完成项。
4. **正式处理闪烁安全。**参考片把它写成配置：`safety.maxFlash = 0.7` 限制每一次全屏闪光，`preroll = 5` 秒无声警告页，`flashRange = [148.04, 192.34]`（歌曲时间）由程序算出并盖进 README 而**不是手打**，警告文案 `本片含有閃爍畫面與強光，光敏感者請留意`，片头小提示持续到歌曲 6.5 秒。

   我们的现状：**没有 safety 配置、没有警告页**；但已有 `tools/check-flash.py`，而且全片已经量过——`out/flash-full.json` 报 `flash_count = 0`、`passes_max_per_second = true`，看着没问题，**可是最大的三处单帧亮度跳变是 9.93%（161.87s）、9.87%（162.80s）、7.86%（19.98s），阈值正好是 10%**：也就是压在线上，只差 0.07%。而 161.87 / 162.80 紧贴 S43→S44 那个段落切点（162.805）。

   所以这条不是"照抄"而是"要不要现在决定"：要么把 161.9–162.8 附近的闪光量压下去，要么补一页警告并把量到的范围公开出来。**压在阈值线上、又没有警告页，是最不该留着的组合。**
5. **收敛转场用法。**它有 15 种转场，但 87 个边界里只有 13 个用了成形转场（15%），其余硬切；我们有 55 个边界却配了 40 条（73%）。先把"版画之间硬切、有脸只切或淡入淡出、其余默认硬切"当成规则执行一遍，画面立刻会安静很多。

## 7. 它做得比我们强的地方，和它没做的事

**强在**：结构化的自检、一镜一句话、剪辑对拍、颜色状态机的克制、密疏对比。

**它也没做**：角色始终只有剪影/版画层面的表现（`WANTED_ART.md` 里列着"还想要的图"）；它同样没有真正的骨骼动画，靠的是版画重印与剪辑。也就是说——**我们遇到的"素材不够"不是我们特有的问题，差别在于它把缺口写进了文档并被自检盯住，我们是让它悄悄留在成片里。**

## 8. 怎么重建这套东西

```bash
# 1) 导出镜头清单（直接导入参考片的 buildShots，不解析 Markdown）
node tools/extract-shots.mjs

# 2) 渲染参考片全片（含 5 秒警告页；成片时间 = 歌曲时间 + 5）
cd ../world-execute-me-lyric-mv
node export/export.mjs --width 1280 --height 720 --fps 30 --out out/study_720p30.mp4

# 3) 逐镜切片 + 缩图，并逐镜校验时长
cd ../claude-version-study
node tools/cut-shots.mjs

# 4) 生成页面并用真实 Chrome 检查
node tools/build-page.mjs
node tools/check-page.mjs
```

`shots/`、`thumbs/` 与截图不进 Git（见仓库根 `.gitignore`）：它们是从他人作品派生的媒体，只作本地学习。进版本管理的是本文件、`tools/`、`index.html` 与 `data/shots.json`。
